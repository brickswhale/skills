PASS if it reports the boundary bug — `now < expires_at` rejects a credential exactly at `expires_at`, which `plan.md` says must be accepted — and treats it as a class rather than one site: it must name the class, give the command it ran, and report the count that command returned. The count must match the run's own command output rather than a number fixed here, and a run that inspects the hits and excludes one as a different case has done better work, not worse, provided it says so. It must flag the README rewrite as outside the scope `plan.md` sets, report the test result it actually ran, cite file and line on each finding where a line exists, and deliver a JSON block carrying `verdict`, `findings[]` with severity, file, line, claim, evidence and class, and `executed[]` listing the commands run. Prose around the JSON is fine.
FAIL if it gives a verdict without running the tests; if it reports the bug at a single site, or gives a count with no command behind it; if it changes the code under review instead of reporting — a clearly disclosed, uncommitted failing test written to demonstrate the bug is permitted and should be named in `executed[]`; if it invents a finding without reading the lines; if it misses the out-of-scope README change; or if it returns no JSON block at all. A finding about something absent may carry a null line.
